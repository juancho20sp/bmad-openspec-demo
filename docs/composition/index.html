El problema
Pedirle código a la IA sin plan
  • La IA inventa lo que no le dijiste.
  • Cada persona le pide cosas distintas: el código no encaja.
  • Nadie sabe qué se decidió ni por qué.
  • El «ya terminé» no se puede comprobar.
Solución: poner por escrito el qué, el cómo y la prueba antes de programar.

La idea central
BMAD planea el proyecto, OpenSpec ejecuta cada ticket
BMAD
  • Para todo el proyecto
  • Responde: ¿qué y por qué?
  • Sale: PRD, arquitectura, historias
OpenSpec
  • Para un ticket a la vez
  • Responde: ¿cómo cambia el sistema?
  • Sale: spec, tareas, código
1 historia de BMAD = 1 rama de Git = 1 cambio de OpenSpec.

Acuerdos
Cuatro reglas para no pisarnos
  • Un repo compartido, una rama por historia: feat/3-1-unirse-grupo
  • Nada se programa sin una spec aprobada por otra persona.
  • Todo cambio entra por Pull Request con revisor distinto al autor.
  • Si la realidad cambia, se actualiza el documento, no solo el código.

const g = getGroup(req.params.id);
if (g.members >= g.capacity) {
return res.status(409).json({ error: 'Grupo lleno' });
}
addMember(g.id, req.studentId);
